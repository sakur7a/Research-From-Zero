# LearnBuddy 开发协作记录模板

此文件仅是空白模板，不是使用证明。依据项目所有者提供的评分文字：LearnBuddy 使用深度占 25%，且开发历史对话是必交材料。具体平台、导出形式、提交权限和期限待主办方规则确认。

## 记录原则

只记录在指定 LearnBuddy 中真实发生的协作。保留原始时间与内容，不补造过去对话；其他平台聊天或 Re0 的运行日志只能按实际来源另列，不能改名为 LearnBuddy 记录。项目运行使用哪个模型，与开发是否使用 LearnBuddy 分别说明。

原始记录保存在合规的私有位置。对外提交副本移除 Key、访问令牌、私人联系方式、未授权论文和敏感研究内容，并标明脱敏。不要默认把原始记录放进公开 GitHub 仓库。没有原始记录链接时写「待补充」，不要伪造链接或完成状态。

### 1. 当时遇到的具体问题

待填写。描述任务、输入、期望与实际行为；不要把后来知道的结论伪装成当时的提问。

### 2. 提供给 LearnBuddy 的材料和问题

待填写。注明代码片段、错误记录或产品约束的来源；截图/摘录应可追溯到原会话。

### 3. LearnBuddy 实际提出的建议

待填写。区分原文摘录和人工摘要；摘要不能扩大或改写其贡献。

### 4. 人工判断与取舍

待填写。写清采纳、修改或否决的内容及原因，不能把模型建议自动视为正确。

### 5. 落地改动

待填写。对应代码/文档路径、提交标识或其他真实产物；未落地时写明原因。

### 6. 验证方法与结果

待填写。记录真实测试命令、用例、结果和时间。明确模拟响应测试、真实模型测试、用户体验测试的区别；失败也应保留。
